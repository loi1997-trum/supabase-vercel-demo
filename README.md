# Bài tập: Todo List + Supabase + GitHub Actions CI/CD + Vercel

Hướng dẫn từng bước để chạy dự án này từ đầu đến khi có CI/CD tự động deploy.

---

## BƯỚC 1: Tạo project trên Supabase

1. Vào https://supabase.com → **Sign up / Log in**.
2. **New Project** → đặt tên, chọn mật khẩu database, chọn region gần bạn (Singapore là gần VN nhất).
3. Đợi project khởi tạo xong (khoảng 1-2 phút).
4. Vào **SQL Editor** (menu bên trái) → **New query** → dán đoạn SQL sau và **Run**:

```sql
create table todos (
  id bigint generated by default as identity primary key,
  task text not null,
  is_complete boolean default false,
  inserted_at timestamp with time zone default now()
);

-- Bật Row Level Security (RLS)
alter table todos enable row level security;

-- Cho phép mọi người đọc/ghi (chỉ dùng cho demo học tập, KHÔNG dùng cho production thật)
create policy "Public access" on todos
  for all
  using (true)
  with check (true);
```

5. Vào **Project Settings** (biểu tượng bánh răng) → **API**:
   - Copy **Project URL** → dán vào `SUPABASE_URL` trong file `config.js`
   - Copy **anon public key** → dán vào `SUPABASE_ANON_KEY` trong file `config.js`

## BƯỚC 2: Test thử ở local

Vì đây là site tĩnh (HTML/JS thuần), bạn chỉ cần mở bằng 1 local server đơn giản (không thể mở trực tiếp file:// vì fetch API sẽ bị chặn CORS):

```bash
# Nếu có Python
python3 -m http.server 8000

# Hoặc dùng VS Code extension "Live Server"
```

Mở trình duyệt: `http://localhost:8000` → thử thêm/xóa/đánh dấu công việc. Nếu chạy được nghĩa là Supabase đã kết nối đúng.

## BƯỚC 4: Tạo project trên Vercel (chỉ để lấy thông tin, KHÔNG dùng auto-deploy của Vercel)

1. Vào https://vercel.com → Sign up/Login bằng GitHub.
2. **Add New → Project** → chọn import repo bạn vừa tạo.
3. Ở bước cấu hình, Vercel tự nhận diện là static site → cứ để mặc định → **Deploy** (deploy lần đầu này sẽ dùng CI/CD có sẵn của Vercel — nó cho phép ta lấy thông tin `ORG_ID` và `PROJECT_ID`).
4. **Quan trọng**: Sau khi deploy xong, vào **Project Settings → Git** → tắt "Automatically deploy" nếu bạn muốn chỉ dùng GitHub Actions để deploy (tránh bị deploy 2 lần trùng nhau). Hoặc bạn cứ để mặc định cũng không sao, chỉ là dư 1 lớp deploy.

### Lấy thông tin cần thiết để cấu hình GitHub Actions:

**a. Lấy VERCEL_TOKEN:**
- Vào https://vercel.com/account/tokens → **Create Token** → đặt tên (vd: `github-actions`) → copy token (chỉ hiện 1 lần).

**b. Lấy ORG_ID và PROJECT_ID:**
Cách dễ nhất — dùng Vercel CLI ở máy local:
```bash
npm install -g vercel
vercel login
vercel link
```
Sau khi chạy `vercel link` và chọn đúng project, nó sẽ tạo ra file `.vercel/project.json` chứa:
```json
{
  "orgId": "xxxxxxxx",
  "projectId": "xxxxxxxx"
}
```
Copy 2 giá trị này ra.

## BƯỚC 5: Thêm Secrets vào GitHub repo

Vào repo trên GitHub → **Settings → Secrets and variables → Actions → New repository secret**, thêm lần lượt:

| Tên secret        | Giá trị                          |
|--------------------|-----------------------------------|
| `VERCEL_TOKEN`     | Token lấy ở bước 4a               |
| `VERCEL_ORG_ID`    | orgId lấy ở bước 4b               |
| `VERCEL_PROJECT_ID`| projectId lấy ở bước 4b           |

> File workflow (`.github/workflows/deploy.yml`) đã được viết sẵn trong project — nó sẽ tự dùng các secrets này.

Ngoài ra cần thêm biến môi trường cho `vercel pull` nhận diện đúng project — cách đơn giản nhất là thêm luôn `VERCEL_ORG_ID` và `VERCEL_PROJECT_ID` như **env** ở đầu file workflow (xem ghi chú trong file).

## BƯỚC 6: Commit và kiểm tra CI/CD

```bash
git add .
git commit -m "Update todo app"
git push
```

Vào tab **Actions** trên GitHub repo → bạn sẽ thấy workflow **"Deploy to Vercel"** đang chạy. Đợi vài chục giây đến khi có dấu ✅ xanh → nghĩa là code đã được tự động deploy lên Vercel production.

Vào Vercel Dashboard → xem URL production → mở thử để kiểm tra thay đổi mới nhất đã lên chưa.

## Luồng hoạt động CI/CD

```
Bạn commit & push code lên GitHub (nhánh main)
        │
        ▼
GitHub Actions tự động được kích hoạt (trigger: push)
        │
        ▼
Job "deploy" chạy trên máy ảo Ubuntu do GitHub cấp
        │
        ├─ Checkout code
        ├─ Cài Vercel CLI
        ├─ Pull cấu hình project từ Vercel (dùng VERCEL_TOKEN)
        ├─ Build project
        └─ Deploy bản build lên Vercel (production)
        │
        ▼
Website production tự động cập nhật code mới nhất
```

## Lưu ý bảo mật

- `SUPABASE_ANON_KEY` an toàn khi lộ ở client-side vì được bảo vệ bởi Row Level Security (RLS). Policy demo trong bài này cho phép public đọc/ghi — **chỉ dùng để học**, không dùng cho app thật.
- `VERCEL_TOKEN` là secret nhạy cảm — không bao giờ commit vào code, chỉ lưu trong GitHub Secrets.
